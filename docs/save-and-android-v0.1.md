# 로컬 저장·Android 첫 빌드 인수 기준 v0.1

2026-10-11 / Codex — 총괄·디자인. 구현 담당 Claude. Q1~Q5 시제품의 재접속과 실제 조작 확인을 위한 범위이며, 저장/Android가 이미 구현됐다는 문서는 아니다.

## 1. 첫 저장 범위

슬롯 1개, 앱 내부 `user://` JSON, `schema_version: 1`. 계정·서버·클라우드 동기화는 이번 범위에 포함하지 않는다. 퀘스트 단계는 enum 번호 대신 안정적인 이름으로 저장한다.

| 저장 대상 | 포함 값 |
| --- | --- |
| 성장·재화 | 레벨·경험치·재화·아이템 |
| 장비·기술 | 무기 ID·강화 단계·제작법·배운 기술 |
| 영물 | 계약 영물·임시 동행·활성 영물·현재 동행/장비 폼 |
| 퀘스트 | 진행 단계, 보상 지급 기록, 선택·수련권 등 플래그 |
| 지도 변화 | 느슨한 줄 조사·고정점/다리·도톰 탐지/잎 표시·Q3 복구·Q4 연결쇠·덮개·Q5 배수·두 손잡이 |
| 재개 위치 | 바깥/던전 구분, 마지막 **안전한 체크포인트**, 정비공의 구조/대기/완료 상태 |

카메라 tween·대화 타자·적 예고·회피·변신 중간 타이머는 저장하지 않는다. 틈 위·난간 안·죽음 중간 위치에서 재개하지 않는다. 보스 전투 중 종료하면 보스 방 입구로 재개하고 보스·정비공 체력과 패턴은 재도전 규칙대로 초기화한다. 앞방 배수와 이미 받은 보상은 유지한다. 다른 단계도 장비/보상 달성을 먼저 확인하고 완료한 일을 중복 요구하지 않는다.

Q4 제작 직후 종료, 줄비 계약 직후 종료, Q5 고리 보관 선택 직후 종료가 핵심 경계다. 상태는 대화 종료 콜백에만 매달지 않고 지속 가능한 퀘스트 상태로 확정한다. 보상 지급 기록과 아이템/재화 증가는 **같은 저장 스냅샷**에 포함한다.

## 2. 저장 시점과 실패 처리

- 퀘스트 진행·보상·계약·제작/강화·선택·안전 체크포인트 도달 후 자동 저장. 모바일 앱이 백그라운드로 전환될 때도 저장한다. 종료 이벤트 하나에만 의존하지 않는다.
- 임시 파일에 쓰고 flush·close 후 마지막 정상 파일을 보관하며 교체한다. 여러 저장 요청은 순서대로 처리하고 오래된 스냅샷이 최신 것을 덮지 않게 한다.
- 불러오기 때 버전·ID·단계·수치·연결 상태를 검증한다. 깨진 현재 파일은 백업을 시도하고 원본을 보존한다. 임의로 진행을 초기화해 정상 로드처럼 보여주지 않는다.
- 신규/계속하기 UI는 실제 저장 존재와 정상 로드 가능 여부에 따른다. 저장 실패를 끝 카드의 “저장 완료”로 가리지 않는다.

## 3. 필수 재접속 확인

| 종료 지점 | 재개 기대 |
| --- | --- |
| Q1 상자 수령·보상 후 | 운반/기술/재화 유지, 보상 중복 없음 |
| Q2 계약 전·후 | 임시 진행/계약/활성 영물 일관성 유지 |
| Q3 틈 이동·실패·완료 | 안전 체크포인트, 결력·대기 재개 규칙 일관성, 복구·되받기 유지 |
| Q4 제작·조기 +1·줄비 계약 | 재료 중복 차감 없음, 기존 +1 달성 인정, 계약 소실 없음 |
| Q5 배수·호위·보스 중 | 배수 유지, 보스 중이면 방 입구와 정비공 안전 대기로 재도전 |
| Q5 고리 선택·마을 귀환·끝 카드 후 | 보관처·보상 유지, +60 재화와 물품 중복 없음, 계속 둘러보기 가능 |
| 저장 중단·잘못된 JSON | 마지막 정상 저장/백업 복구 또는 명시적인 오류 안내 |

첫 실행과 두 번 연속 불러오기를 모두 확인한다. 실제 저장 파일로 종료·새 프로세스 재시작을 사용한다. 메모리 변수 재설정만으로 재접속을 통과했다고 기록하지 않는다.

## 4. Android 첫 빌드

개발 PC의 **실제 Godot 버전과 동일한 export templates**를 사용한다. 현재 개발 기준은 4.7.2이며 클라우드 4.6.3의 테스트와 혼용해 빌드 결과를 표기하지 않는다. Android SDK/JDK·템플릿·디버그 APK 출력 경로와 명령을 문서에 남긴다.

첫 산출물은 설치 가능한 **디버그 APK**다. 배포·스토어 업로드·운영 서명은 이번 작업의 필수 조건이 아니다. 패키지 ID는 임시 개발용으로 고정하고 프로젝트 제목 전체 변경은 하지 않는다. 키·비밀번호·사용자 경로 등 환경별 값은 저장소에 넣지 않는다.

세로 화면·안전 영역·터치 버튼 위치·호환 렌더러·앱 비활성/재개를 확인한다. 키보드 대체 조작은 휴대폰 안내에 표시하지 않는다. Windows의 `C:\Users\my\Desktop\output\`은 사용자의 로컬 출력 경로이므로 **그 PC에서** APK를 복사한다. 클라우드에서 해당 Windows 경로에 저장했다고 기록하지 않는다.

## 5. 실제 기기 첫 점검

1. 이동 손가락을 유지한 채 회피·기술·영물 버튼을 누르는 멀티터치.
2. 초상화 짧게/길게 누르기가 의도한 한 행동만 발생하는지.
3. 대화·퍼즐·작업대·끝 카드의 글자와 터치 영역, 노치/하단 제스처 영역.
4. 보스 방출을 실제 전투 위치에서 보고 수문을 내린 뒤 안전 발판에 머물 수 있는지. 소요 시간·실패 위치를 기록한다.
5. Q1~Q5 진행 중 앱을 백그라운드로 보내거나 강제 종료한 뒤 재접속.
6. 장시간 전투 프레임률·발열·읽기 가능한 공격 예고. 기기 모델·OS·프레임률 측정 방법을 함께 기록한다.

APK 설치 성공, 데스크톱 테스트 통과, 실제 멀티터치 성공을 각각 구분한다. 첫 APK는 교육원 아트 적용이 일부 남아도 만들 수 있다. 저장·조작 검증을 위해 다음 지역 전체나 추가 성장 시스템을 먼저 구현할 필요는 없다.
